The dashboard is finished, and Lectures, Resources, Assignments (with grading)
and Student Approvals are all built and tested. Quizzes and attendance reports
are not started. Before you try uploads locally, Apache needs one sudo change
(below).

The dashboard is `pages/dashboard.php`, at
http://localhost/myProject/SmartClass/pages/dashboard.php.

Testing was done over real HTTP as a teacher, the demo student, a second
teacher and a student outside the class, plus screenshots at desktop and phone

rows.

## Action needed

Your Apache service is set to treat everything under `/home` as read-only, so
it can't save uploads. To allow it:

```
sudo systemctl edit apache2
#   [Service]
#   ReadWritePaths=/home/khairullah/Documents/VS-Code/myProject/SmartClass/uploads /home/khairullah/Documents/VS-Code/myProject/SmartClass/logs /home/khairullah/Documents/VS-Code/myProject/SmartClass/sessions
sudo systemctl restart apache2
```

Uploads were tested on a copy of the project under PHP's built-in server,
pointed at the same database. On cPanel this isn't a problem.

## Security review

- **Fixed, critical:** `ajax/handler.php` had old upload handlers that saved
  files under the user's own filename in a web-accessible folder; a `.php`
  upload could be run on the server. Those and the other unused handlers with
  no access checks were removed. `getClassDetails` and `getClassMembers` now
  check class membership; before, any logged-in user could read any class's
  join code and member emails.
- **Every new page:** prepared statements only; output escaped (verified with
  `<script>` test data); CSRF checked on every POST, including AJAX; role and
  class membership checked on the server for every view, download, grade and
  delete. Each was tested against a second teacher and an outside student.
- **Uploads:** type checked by extension and real content, size capped, random
  file names, files served only through access-checked download pages, and PHP
  blocked anywhere under `uploads/`.
- **Open, in existing code:**
  - The old auth and class pages encode text when saving, so names display as
    `O&#039;Brien`. The fix needs a one-off cleanup of stored data.
  - Class codes use `rand()`, which is predictable.
  - Logout is a GET link.
  - `setup.php` has no CSRF tokens, so delete it after installing.
